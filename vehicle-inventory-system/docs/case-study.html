§2 Architecture

One Spring Boot process serves both the JSON API and the static admin UI. It talks to Supabase in exactly two ways: JDBC for the relational data, and a plain REST call to Supabase Storage for photos — no Node-oriented client SDK, no extra service to run.

§3 Data model & validation

Vehicle

brand, model, year, engine, VIN, mileage, purchase/selling price, status, condition, notes, photos, dateAdded, lastUpdated — every field from the brief, no more.

VIN validation

Enforced as the real 17-character format (letters/digits, excluding I/O/Q), unique at both the application and database level — not just "some text".

Status & condition

Enums (AVAILABLE, RESERVED, SOLD, IN_TRANSIT, IN_SERVICE; NEW, USED, CERTIFIED_PRE_OWNED, SALVAGE), exposed via /api/lookups/* so the UI never hard-codes them.

VehiclePhoto

One vehicle to many photos; each row tracks its own Storage path (for clean deletion), display order, and a single "primary" flag for the list/dashboard thumbnail.

05

§5 Security

  • Stateless JWT — one admin role, since this is an internal tool rather than a multi-tenant product. No server-side session state to manage or scale.
  • 401 vs. 403, actually correct — a missing/invalid token gets 401; this took an explicit fix during testing (§7) because Spring Security's default for a pure-JWT setup is a bare 403.
  • Secrets stay in the environment — JWT signing secret, Supabase service-role key, and the initial admin password are all read from environment variables. Nothing sensitive is committed.
  • Passwords are never handled in plaintext beyond the login request itself — BCrypt at rest, and the first admin account is seeded once, from an env var, on an empty database.

§7 Testing & verification

15 automated tests (Mockito unit tests on the service layer; full-context MockMvc tests for auth, CRUD, validation, and search) all pass. More usefully for a bid: the app was actually started and driven through the browser — login, add a vehicle, confirm it shows up filtered correctly, confirm the dashboard math is right — not just trusted to work because the tests were green. §8 Running it

No Supabase project needed just to try it out — the dev profile uses an in-memory H2 database:

export APP_ADMIN_SEED_PASSWORD=ChangeMe123!
mvn spring-boot:run
# -> http://localhost:8080, sign in with admin / ChangeMe123!

Photo upload needs a real Supabase project (a public Storage bucket + the service-role key) — full setup steps are in the repo's README. Everything else works with nothing but a JDK.
